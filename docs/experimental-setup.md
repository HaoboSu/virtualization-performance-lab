## Initial Experimental Variable

The first phase varies the CPU load generated by VM2 while measuring VM1 performance.

| Condition | VM2 CPU Load |
|---|---:|
| Baseline | 0% |
| Light | 25% |
| Medium | 50% |
| High | 75% |
| Heavy | 100% |

The accepted pilot used the 0%, 50% and 100% conditions. The formal-v1 protocol expands this to all five conditions.

## Initial Pilot Plan

- **Benchmark:** `sysbench cpu`
- **Threads on VM1:** 1
- **Duration per run:** 30 seconds
- **Pilot repetitions per condition:** 5
- **Initial formal repetitions per condition:** 10
- **Possible formal extension:** 20 repetitions per condition after a data-quality check

### Baseline command on VM1

```bash
sysbench cpu --threads=1 --time=30 run
```

### Contention command for smoke-v2 and formal-v1 on VM2

```bash
stress-ng --cpu 2 --cpu-load 50 --cpu-method int64 --timeout 120s
```

The fixed `int64` method is supported by [stress-ng 0.17.06](https://github.com/ColinIanKing/stress-ng/blob/V0.17.06/stress-cpu.c). It holds the kind of CPU work constant while configured load varies. Earlier pilot and smoke-v1 runs used the default method; preserve them as separate datasets.

## Important Methodological Note

Because the host uses VMware Workstation on Windows, the exact placement of each VM's vCPU on host logical processors is controlled by VMware and the Windows scheduler.

An attempted process-level affinity experiment was rejected because restricting the complete `vmware-vmx.exe` processes produced an unstable baseline. The accepted pilot and formal-v1 protocol therefore use default host scheduling and do not apply Windows process affinity. This limitation must remain explicit when interpreting the results.

---

## Experimental Controls

During formal measurements:

- keep the laptop connected to AC power;
- use the same Windows power mode throughout;
- close unnecessary applications and browser tabs;
- pause large downloads, cloud sync, and updates;
- keep VM CPU/RAM settings unchanged;
- keep guest kernel and benchmark versions unchanged;
- avoid changing VMware settings between conditions;
- allow a short cooldown between batches if host temperature rises substantially.
