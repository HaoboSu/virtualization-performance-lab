## Initial Experimental Variable

The first phase varies the CPU load generated by VM2 while measuring VM1 performance.

| Condition | VM2 CPU Load |
|---|---:|
| Baseline | 0% |
| Light | 25% |
| Medium | 50% |
| High | 75% |
| Heavy | 100% |

The initial pilot experiment will use shorter runs and fewer repetitions before the full campaign.

---

## Initial Pilot Plan

- **Benchmark:** `sysbench cpu`
- **Threads on VM1:** 1
- **Duration per run:** 30 seconds
- **Pilot repetitions per condition:** 5
- **Formal repetitions per condition:** 20 (after validating the pilot)

### Baseline command on VM1

```bash
sysbench cpu --threads=1 --time=30 run
```

### Example contention command on VM2

```bash
stress-ng --cpu 1 --cpu-load 50 --timeout 30s
```

---

## Important Methodological Note

Because the host uses VMware Workstation on Windows, the exact placement of each VM's vCPU on host logical processors must be controlled or documented before drawing strong conclusions about CPU contention.

The pilot experiment will first verify that contention produces a measurable effect. If necessary, host CPU affinity will be configured so that the benchmark VM and contention VM compete for the same host logical processor.

---

## Experimental Controls

During formal measurements:

- keep the laptop connected to AC power;
- use the same Windows power mode throughout;
- close unnecessary applications and browser tabs;
- pause large downloads, cloud sync, and updates;
- keep VM CPU/RAM settings unchanged;
- keep guest kernel and benchmark versions unchanged;
- avoid changing VMware settings between conditions;
- allow a short cooldown between batches if host temperature rises substantially.

---

## Data Integrity

All results in this repository will come from experiments performed on the author's own computer.

No proprietary company infrastructure, customer data, production configuration, or confidential monitoring data will be used.
